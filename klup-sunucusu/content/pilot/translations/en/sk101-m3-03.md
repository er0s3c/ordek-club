# What does a 403 response prove?

> Editorial draft. Technical and language review are pending; this is not published pilot content.

## The case

A status code summarises the server's response to a request. Receiving a 403 does not mean that the request achieved authorised access; nor does it show that DNS never worked at all. Examine the headers, the account and the resource together. Recording the error code as an observation rather than a root cause prevents a misdirected response.

## Synthetic evidence

```text
HTTP/1.1 403 Forbidden
Content-Type: application/json
```

## Investigation steps

1. Record the status code
2. Inspect the request and account context
3. Write the cause after testing it with additional evidence

Key term: **status**.

## Remember

- An HTTP response was received and access was refused.
- Keep observations separate from assumptions.
- Record the evidence, the scope and the reason for the next step.
