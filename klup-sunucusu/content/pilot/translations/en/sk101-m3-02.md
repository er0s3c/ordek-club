# Why is a session identifier guarded like a secret?

> Editorial draft. Technical and language review are pending; this is not published pilot content.

## The case

An application can hold context between HTTP requests with a session identifier. A valid session token can open account operations to whoever uses it. HttpOnly, Secure and SameSite limit different risks; none of them replaces object-level authorisation. How sessions are invalidated on the server after sign-out and a password change must also be examined separately.

## Synthetic evidence

```text
Set-Cookie: session=synthetic; HttpOnly; Secure; SameSite=Lax
```
