# How do you separate change from a PowerShell query?

> Editorial draft. Awaiting technical and language review; this is not published pilot content.

## Incident

PowerShell can both investigate and administer. Before you run a command you need to understand what it reads and what it changes. Don't collect real account secrets just to record the output. In training, start with read-only commands and synthetic output; discuss operations that need privilege with the authorised owner.

## Synthetic evidence

```text
Read-only example: Get-LocalUser
Synthetic output: lab-reader Enabled=True
```

## Review steps

1. Read the purpose of the command
2. Separate the read and change effects
3. Record the output with minimal data

Key concept: **PowerShell**.

## Remember

- A query's output is not permission to make changes.
- Separate observations from assumptions.
- Record the evidence, the scope and the reason for the next step.
