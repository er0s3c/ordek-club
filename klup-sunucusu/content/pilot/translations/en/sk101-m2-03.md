# What can we learn from a DNS response?

> Editorial draft. Technical and language review are pending; this is not published pilot content.

## The case

DNS provides resource records, such as an address, for a domain name. Getting a correct DNS answer does not show that you can reach the application or that you are authorised there. Caching and the type of record queried both affect your interpretation. Split the problem into the name resolution, connection and application stages to work out which step failed.

## Synthetic evidence

```text
Question: portal.mavifener.example A
Answer: 192.0.2.40
TTL: 300
```

## Investigation steps

1. Read the name and type that were queried
2. Record the answer and the TTL
3. Examine the connection with separate evidence

Key term: **DNS**.

## Remember

- This record shows name resolution; it does not show application authorisation.
- Keep observations separate from assumptions.
- Record the evidence, the scope and the reason for the next step.
