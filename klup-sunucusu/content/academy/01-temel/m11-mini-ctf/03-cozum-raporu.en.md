# Practice: The solution report

> Finding a flag works once. **Writing down how you found it** works next time too.

::cizgi[m11-03-sahne]

## Submission rules

- **One** report per team, within 48 hours of the end of the CTF.
- The template below for each solved mission; a "what we tried" section for the ones you couldn't solve.
- **Don't write** the flag itself in the report (say "flag found" instead of `ORDEK{...}`) — the report may later be shared with other students.

## Template (per mission)

```text
Mission: [name] · Area: [1–8] · Solved by: [names]

1. What was given?
   (file, address, description — one sentence)

2. First observation
   (the file's type, what stood out)

3. Solution steps
   - Step 1: command/tool + why
   - Step 2: ...
   (Write the commands in a form that can be copied.)

4. How was the flag reached?
   (without writing the flag)

5. What did we try that didn't work?

6. Real-life equivalent and defence
   (How would this vulnerability/technique be prevented on a real system?)
```

## Assessment

| Criterion | Points |
|---|---:|
| Can someone else repeat the steps? | 4 |
| Is the "why" explained (not just the "what")? | 3 |
| Are the failed attempts written down honestly? | 1 |
| Is the defence recommendation realistic? | 2 |

## ✅ Remember

- A good report is one someone else can walk the same path with.
- The answer to "why" is worth more than the points.
- Every technical finding ends with a defence recommendation.
